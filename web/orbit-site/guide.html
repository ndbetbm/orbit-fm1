ORBIT 1.0 / PUBLISHING GUIDE

はじめてのビルドと公開。

この一式は、Macに実機用の開発環境を入れず、GitHub ActionsのLinux環境でORBIT 1.0をコンパイルする構成です。ブラウザー版はローカルでビルド・検証済み。実機用のコンパイル、書き込み、起動、純正復帰はまだ未検証です。ワークフローは用意済みですが、GitHub上での成功は未確認です。

1. 用意するもの

  • GitHubアカウント、GitHub Desktop、配布した ORBIT-1.0-source.zip。リリースキットの場合は展開したフォルダー内のソースを使います。
  • 公開リポジトリを使用します。ソースと公開ページは誰でも閲覧できるため、秘密情報や個人のバックアップを追加しないでください。
  • 実機更新にはFM-1、データ通信対応USBケーブル、デスクトップ版ChromeまたはEdgeが必要です。

2. GitHubにソースを置く

  1. GitHubでアカウントを作成し、GitHub Desktopをインストールしてログインします。
  2. GitHub Desktopの File → New repository を選び、Nameを orbit-fm1 として新規リポジトリを作ります。
  3. ソースZIPを展開します。build.sh、firmware、web、tools、firmware/engines、.github などを、作ったリポジトリの直下へコピーします。ORBIT-1.0フォルダーごと一段下に入れないでください。ZIP自体をアップロードするだけでは動きません。
  4. Macでは Command + Shift + . で隠しファイルを表示し、.github/workflows/orbit-release.yml が入っていることを確認します。配布版のenginesは変更済みソースを同梱しています。上流のサブモジュールに置き換えないでください。
  5. Summaryに ORBIT 1.0 と入力し Commit to main → Publish repository。Keep this code privateのチェックを外して公開します。

3. 実機用ファームウェアをコンパイルする

  1. GitHubのリポジトリページで Actions → Build ORBIT 1.0 → Run workflow を開きます。ブランチはmain、Publish…はオフのまま実行します。
  2. Linux上でJieLiツールチェーンとAC79 SDKを取得し、sh build.sh --release 1.0 を実行します。その後ブラウザー版のビルドとテスト、サイトの組み立てを行います。
  3. 完了して緑のチェックになった実行を開き、Artifactsから ORBIT-1.0-firmware と ORBIT-1.0-website をダウンロードします。前者に felucca-1.0.fwsc、SHA256SUMS、ライセンスが含まれます。ファイル名は上流のパッケージ仕様に合わせています。画面のバージョンはORBIT 1.0です。
  4. 赤い×なら失敗した工程を開きログを確認します。JieLi配布サイトやGiteeへの接続失敗なら時間を置いて再実行します。コンパイラーやメモリー配置のエラーなら修正が必要です。失敗時は公開処理へ進みません。

ツールチェーンは上流の配布URLから取得します。SDKは指定タグと既存ビルダーのファイルハッシュで照合します。外部配布先の変更・停止でビルドできなくなる可能性があります。ビルド成功は実機動作の保証ではありません。

4. GitHub Pagesで公開する

  1. リポジトリの Settings → Pages → Build and deployment → Source を GitHub Actions に変更します。
  2. Actions → Build ORBIT 1.0 → Run workflow を再び開き、今回は Publish to GitHub Pages… をオンにして実行します。
  3. ビルド・テスト成功後にdeployが実行されます。実行結果のgithub-pagesに表示されるURLを開きます。通常は https://アカウント名.github.io/orbit-fm1/ です。
  4. トップページ、ブラウザー試奏、更新画面、純正復帰画面、ソースダウンロード、公開ガイドをそれぞれ確認します。更新画面ではファイル検証後に更新ボタンが有効になります。実機の初回テスト前には未検証表示を残してください。

独自ドメインは不要です。公開後に変更したらGitHub DesktopでCommit → Push originし、同じワークフローを再実行します。このワークフローは手動実行です。公開は自分のGitHubアカウントから行い、今回のローカル作業だけでは公開されません。

5. FM-1をWebから更新する

  1. 現在の制作データを、そのファームウェアが対応する方法でPCへバックアップします。純正のデータをORBITでそのまま開けるわけではありません。
  2. FM-1をUSBでPCへ直接接続し、DAWなど他のMIDIアプリを閉じます。ChromeまたはEdgeで公開URLの「更新・復帰の管理画面」を開きます。
  3. ORBIT 1.0のパッケージが読み込まれたことを確認して更新ボタンを押します。ブラウザーのMIDI / SysExアクセスを許可し、画面の指示に従います。複数台のFM-1は同時接続しないでください。
  4. 完了まで電源・USB接続を維持します。再起動後、ORBIT 1.0表示、4トラック発音、ノブ、PLAY、プロジェクト保存と電源再投入後の読み込みを確認します。音量を小さくして開始してください。

Web更新機能は上流の更新プロトコルを使用しています。実機で検証が済むまでは配布ページ上で未検証であることを明記します。ブラウザー版のWASMファイルは実機へ書き込むファイルではありません。

6. 純正V15に戻す

  1. M-VAVE公式FM-1ページまたはダウンロードページでV15を入手し、展開した未変更の FM-1.fwsc を用意します。配布サイトには純正ファイルを同梱しません。
  2. 更新画面の「公式V15に戻す」を開き、そのファイルを選びます。サイズ・SHA-256・構造が対応するV15と一致した場合だけ受け付けます。新しい版や別ファイルを拒否したときに検証処理を外さないでください。
  3. 「バックアップして公式V15へ戻す」を押すと、ORBIT/Felucca側のデータを先にPCへ保存します。保存ファイルを確認してから、画面の確認ダイアログを承認します。
  4. 更新完了と純正の起動を確認します。ORBITのプロジェクトは純正では開けません。ORBITへ戻した後の全体バックアップ復元には、更新画面から開くエディターのバックアップ機能を使います。エディターの旧ステップ編集画面はORBITのユークリッド編集には使わないでください。

「更新中断の再開」は、全体バックアップをすでにPCへ保存している場合のみ選びます。USB更新へ応答しない状態ではWebだけで復旧できないことがあります。FM-1-transporterの復旧手順を確認してください。

7. よくある問題

  • Actionsが表示されない：.github/workflows/orbit-release.yml がmainブランチ直下にあるか確認。
  • Pagesが404：SourceがGitHub Actionsか、deployが成功したか、URL末尾のリポジトリ名が正しいか確認。
  • 試奏で無音：電源ボタンを押してからPLAY。OSの音量と出力先も確認。
  • 「実機用パッケージはビルド待ち」：ローカル試作サイトです。Actionsで生成したwebsiteには実機用ファイルが入ります。
  • MIDIが使えない：デスクトップ版Chrome / Edge、HTTPSまたはlocalhostで開き、ブラウザーのMIDI権限を確認。
  • 初回実機検証の記録：FM-1の元バージョン、書き込んだファイルのSHA-256、起動、音声、保存、純正復帰の結果を記録し、確認できた範囲だけを公開ページに反映。
